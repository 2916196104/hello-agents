# 风险：TerminalTool 白名单为 POSIX 工具，但执行壳是 Windows cmd

现象：TerminalTool 白名单含 cat/grep/ls/find/head/wc 等 POSIX 命令，但实际执行环境为 Windows cmd.exe：
- cmd 下 ls/cat/grep/find/head/pwd/whereis/type 全部报 "'xxx' is not recognized"。
- 未被白名单的 findstr/type 反而被拒绝 → 白名单与真实平台严重错配。
- 变通：`bash -c "..."` 可正常运行（Git Bash），但 bash 继承的 PATH 里没有 python（`python: command not found`）。
- python 在 cmd 下可用（3.12.10），仅 cmd 内可直接机场。

影响：CodebaseMaintainer 系统提示声称"可执行 ls, cat, grep, find, git"，Agent 直接调用这些命令会反复失败，需回退到 bash -c 包装，且脚本内 subprocess 调用的命令名同样需重写。

建议：按平台选择命令集或统一走 `bash -c`；把白名单改为"可执行文件真实可解析"，并对 bash -c 内的命令做二次校验（否则白名单可被 bash -c 绕过，存在安全逃逸风险）。
